---
name: lessons
description: Turn a finished job, launch, failure or surprise into a lesson and a reviewed change. Use at the end of every job.
---
1. Append one row to this repo's docs/lessons.md (by PR): date, what happened, evidence URL, lesson, change. Do not write to the studio hub; the studio's own agents pull lessons into studio-hub.
2. State the lesson as a principle, not the example. Do not encode the specific case.
3. If it repeats, propose one change: a line in CLAUDE.md, a skill edit, a test, or a hook. Open it as its own draft PR. Instruction, skill and hook changes get an independent review like code.
4. Cap new rules at one or two per job. Remove a rule that adds friction without value.
5. Record the next learning signal to check (page views, test result, user feedback) and when.
